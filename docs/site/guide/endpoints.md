# 节点与协议端

## 节点

Docker 节点通常对应一台主机；Kubernetes 节点对应一个受限 namespace 运行池。不要复制同一份 node-credential.json 同时运行多个 Agent。

首次注册使用 ENROLLMENT_TOKEN，成功后凭据持久化在 NODE_STATE_DIR。后续重启使用持久凭据，不需要重新创建节点。

## NapCat

创建后启动协议端，在平台查看二维码并扫码。只有需要重新登录时才手动刷新二维码。QQ 风控退出会体现为离线/重新扫码，而不是简单的容器异常。

## OneBot

优先反向 WebSocket：NapCat 主动连接业务平台，配置业务平台提供的地址和 token。正向 WS 则要求业务平台能够访问协议端的监听端口；仅保存配置不会自动发布公网端口。

管理端口 6099 不提供给业务客户端，也不要发布到公网。

## 操作

停止保留登录数据。重启保留数据；Docker 强制重启保留容器，Kubernetes 重启替换 Pod。删除协议端会清理关联运行数据，请先备份。
